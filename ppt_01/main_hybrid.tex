\WinterWorkflowFrame{Vibe Coding 工作流}{%
  \WinterWorkflowStep{1}{先用一句话说明用户、目标和成功标准，避免模型只优化局部代码}
  \WinterWorkflowStep{2}{让模型生成最小可运行版本，并要求列出关键假设和依赖}
  \WinterWorkflowStep{3}{通过运行、截图、日志和测试结果持续反馈，而不是只说感觉不对}
  \WinterWorkflowStep{4}{把稳定下来的能力沉淀为组件、脚本或模板，减少重复提示}
  \WinterWorkflowStep{5}{最后做人工审阅，重点检查边界条件、安全性和维护成本}
}

\WinterFindingFrame
  {收益与风险}
  {assets/image11.jpeg}
  {关键发现}
  {Vibe coding 带来了什么}
  {最大收益是把低确定性的探索阶段大幅压缩，让用户更快看到可运行结果。主要风险是模型会自信地生成错误实现，并在需求含混时扩大偏差。因此，vibe coding 更适合作为加速器，而不是替代工程判断。}
